# BugFix-261014-0001: 修复外来 non-standard speak 标签导致 CosyVoice TTS 产生超长死寂空白

## 一、缺陷描述
用户在录入或粘贴旁白解说词时（例如从剪映或其他平台导出的带音效配置文本），包含如下片段：
```text
他们说，喜欢一个人是藏不住的，眼神会出卖你，语气会出卖你。可我不太确定，喜欢这东西

<speak effect="eq" effectValue="0 2 2 3 4 3 0 -4"> 他们说，喜欢一个人是藏不住的，眼神会出卖你，语气会出卖你。可我不太确定，喜欢这东西，到底该怎么判断呢？如果心跳加速就算数，那刚才路过那家甜品店，我心跳得厉害，但我知道，我只是馋那块提拉米苏而已。如果坐立不安就算数，那每次点开消息列表，看见红点亮起又熄灭，那种失重感又算什么呢？也许喜欢根本没有标准答案。它更像今天下午四点的阳光，温暖却不刺眼，你站在那里，不用开口，身体就先知道了。喂，你说，是这样吗？还是说，连我自己都还没学会承认？ </speak>
```
在调用本地 CosyVoice3 接口生成配音后，生成的音频中出现异常的超长大段空白无声内容。

## 二、测试分析与根因排查
经过对不同输入片段与本地 CosyVoice3（端口 8890）服务端 API 的实测对照与 FFmpeg `silencedetect` 静音检测分析：
1. **语气词排查**：
   - 对“喂，你说，是这样吗？还是说，连我自己都还没学会承认？”及所有感叹词/语气词进行纯文本合成测试，检测结果为 **0 秒异常静音**，朗读连贯自然。说明**语气词（如“喂”）完全正常，并不是导致空白的原因**。
2. **标准 SSML 排查**：
   - 使用标准 `<speak>...</speak>` 包装合成，检测结果仅为正常标点换气停顿（约 0.58 秒），无死寂空白。
3. **根因定位**：
   - 当输入携带 `<speak effect="eq" effectValue="0 2 2 3 4 3 0 -4">` 属性标签时，CosyVoice 的 SSML 解析器由于不识别该非标音效属性（`effect="eq"` 是剪映等音频处理宿主的专有参数），在处理音频分片时产生解析异常，直接输出了**长达 10.825 秒的纯零死寂无声音频数据**（从 1.30s 持续到 12.13s）。
   - 此外，文本头部存在一段未闭合的重复句子，导致同一句话被重复朗读。

## 三、修复方法与实现
1. **多重非标标签清洗与净化**：
   - 在 `src-tauri/src/tts_service.rs` 的 `parse_script` 解析器中增加正则清洗规则：
     - 使用 `(?i)</?speak[^>]*>` 自动剔除任何外部传入的 `<speak ...>` 及 `</speak>` 标签，防止非标属性直接透传至 TTS 引擎底层导致音频缓冲静音。
   - 保留合法的停顿标记转换：将 `[break=Xms]` 规范化转换为内部支持的标准 `<break time="..."/>`。
2. **多余换行与标点规范化**：
   - 将连续换行 `\r\n` 安全转为单逗号停顿，并清理可能形成的重复逗号（`，，` -> `，`），避免引起引擎不必要的超长间隔停顿。

## 四、涉及与修改代码清单
- `src-tauri/src/tts_service.rs`: 在 `parse_script` 中增加全局正则清洗非标 `speak` 标签与标点规整逻辑。
