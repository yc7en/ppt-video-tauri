# BugFix-261013-0004: 修复本地 CosyVoice TTS 接口 422 请求体校验异常

## 一、缺陷描述
在系统设置中配置本地 TTS Base URL 为 `http://127.0.0.1:8890/api/v1/services/audio/tts/SpeechSynthesizer` 后，在编辑文案页面点击【🎤 生成配音】报错：
`TTS 生成失败: Local TTS Error (422 Unprocessable Entity): {"detail":[{"type":"model_attributes_type","loc":["body","input"],"msg":"Input should be a valid dictionary or object to extract fields from","input":"..."}]}`。

## 二、修复方法与实现
1. **根因定位**：
   - 本地 `8890` 服务为仿阿里云 SDK 的 FastAPI 实现，要求请求体遵从 `AliTTSRequest` 架构，其中 `input` 必须是一个包含 `text`, `voice`, `format`, `sample_rate`, `rate` 的对象；
   - 客户端原代码在检测到 `127.0.0.1` 时误匹配为了 OpenAI 格式分支，把 `input` 当作普通字符串传输（`{"input": "文本内容"}`），被本地 Pydantic 校验器拦截拒绝。
2. **修复措施**：
   - 重构 `TtsService::call_tts_api` 请求体构造逻辑，对 `SpeechSynthesizer` 端点专门使用合规的 `AliTTSRequest` 对象载荷；
   - 增加 Base URL 智能补全机制，用户若仅输入 `http://127.0.0.1:8890` 亦能自动挂载正确路径；
   - 同步保留对云端官方 DashScope 与标准 OpenAI `/audio/speech` 格式的向后兼容；
   - 在后台 `probe_duration` 及音频静音生成中统一追加 `CREATE_NO_WINDOW` 标志。

## 三、涉及与修改代码清单
- `src-tauri/src/tts_service.rs`: 适配 `SpeechSynthesizer` JSON 架构，追加 URL 规整及进程静默处理
