# R-261020-0001: 支持上传并解析 PDF 演示文档

## 一、变更背景与原因
用户反馈在首页新建项目时，当前仅允许选择 `.ppt` 和 `.pptx` 格式，无法上传 PDF 格式文件。而在许多场景下，演讲者、教师或团队会将演示文稿导出为 PDF 发送，或者直接制作 PDF 格式幻灯片。为满足多样化输入格式诉求，需要支持上传并高保真解析 PDF 文档。

## 二、变更具体内容
1. **文件选择对话框过滤器扩展**：
   - 在 `select_ppt_file_cmd` 中扩展文件过滤规则，支持 `.pptx`, `.ppt`, `.pdf` 混合选择与单独过滤；
   - 对话框标题与描述更新为支持 PPT 及 PDF。
2. **免依赖原生 PDF 高保真渲染引擎（WindowsNativePdfParser）**：
   - 考虑到绿色便携版免安装要求（严禁依赖系统 Python、Ghostscript 或 Poppler），基于 Windows 10/11 内置的 WinRT UWP API（`Windows.Data.Pdf.PdfDocument`）实现无外部依赖的高性能矢量渲染；
   - 自动将 PDF 各页面渲染为 1920 宽度、超高保真无损 PNG 切片，写入项目 `slides/` 目录；
   - 构建 `UniversalPresentationParser` 统一入口，按扩展名自动路由分流（`.pdf` 走原生 WinRT 解析，`.ppt`/`.pptx` 走 Office COM 自动化）。
3. **前端界面文案与交互体验优化**：
   - 顶部步骤栏更新为「① 上传 PPT / PDF」；
   - 首页卡片标题更新为「新建项目（选择并解析 PPT / PDF）」，提示信息明确说明支持 `.pptx / .ppt / .pdf`；
   - 统一优化异常提示文案为「解析文档失败」。

## 三、涉及与修改的代码文件
- `src-tauri/src/ppt_parser.rs`: 新增 `WindowsNativePdfParser` 与 `UniversalPresentationParser`，集成 Windows WinRT 原生 PDF 渲染切片能力
- `src-tauri/src/project_manager.rs`: `create_project` 接入 `UniversalPresentationParser`
- `src-tauri/src/commands.rs`: `select_ppt_file_cmd` 增加 `.pdf` 文件过滤器
- `src/App.vue`: 更新步骤栏、新建卡片文案、文件选择提示语及错误处理

## 四、测试与验证
- 实测将多页 PDF 文件导入系统，通过 PowerShell 无窗口后台静默调起 WinRT 接口，以 1920 宽度成功渲染各页 PNG 切片；
- 切片图像自然编码并正常加载缩略图 Base64，与现有文案编辑、TTS 合成与视频生成管线完美兼容。
