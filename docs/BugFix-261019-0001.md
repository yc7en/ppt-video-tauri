# BugFix-261019-0001: 修复阿里云 DashScope SpeechSynthesizer 返回 JSON 导致多段音频拼接失败

## 一、缺陷描述
用户在使用 DashScope `SpeechSynthesizer` 接口与 `cosyvoice-v3-flash` 模型生成多句配音时，前端弹窗报错：
> `tauri.localhost 显示`
> `TTS 生成失败: 多段音频拼接失败`

## 二、测试分析与根因排查
1. **接口行为排查**：
   - 当用户配置 `api_url` 为 `https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer` 时，请求命中了 Rust 端的 `if url.contains("SpeechSynthesizer")` 分支；
   - 本地模型（如 `http://127.0.0.1:8890`）的 `SpeechSynthesizer` 接口直接返回二进制音频流（`audio/mp3` 或 `audio/wav`）；
   - 但阿里云官方 DashScope 云端 `SpeechSynthesizer` 接口返回的是 HTTP 200 的 JSON 数据：
     ```json
     {
       "output": {
         "audio": {
           "url": "http://dashscope-result-bj.oss-cn-beijing.aliyuncs.com/.../xxxx.mp3"
         }
       }
     }
     ```
2. **根因定位**：
   - 原代码在 `SpeechSynthesizer` 分支下直接执行 `fs::write(output_path, bytes)`，将 462 字节的 JSON 文本直接作为 `spk_0000.mp3` 写入了磁盘；
   - 在多句或包含换行/停顿的文案合成时，`synthesize_slide_audio_with_timing` 会调用 FFmpeg `concat` 滤镜合并各个分句切片；
   - FFmpeg 尝试读取 `spk_0000.mp3` 时发现不是有效 MPEG 音频（报 `[mp3] Failed to find two consecutive MPEG audio frames / Invalid data found when processing input`），进程异常退出（返回码为非零），最终抛出 `多段音频拼接失败`。
   - 此外，原 FFmpeg concat 列表中直接使用了 `.canonicalize()`，在 Windows 环境下会生成带 `//?/` 扩展前缀的 UNC 路径；若遇到各音频切片参数或采样率微小差异，`-c copy` 亦缺乏回退重编码保护。

## 三、修复方法与实现
1. **统一智能音频提取函数 `save_audio_from_bytes`**：
   - 在 `tts_service.rs` 中增加通用的音频解析落地函数：
     - 若响应以 `{` 开头（JSON 格式）：
       1. 检查是否存在错误字段（`message`、`error`、`code`），有则直接抛出友好报错信息；
       2. 提取音频 URL（支持 `/output/audio/url`、`/output/audio_url`、`/output/audio`、`/audio_url` 等多种结构），并自动发起 HTTP 请求将 OSS 上的真实音频流下载保存到目标路径；
       3. 支持 Base64 编码音频提取解码；
     - 若响应为原始二进制流，则直接写入文件。
   - 将 `SpeechSynthesizer` 分支、`OpenAI (/v1/audio/speech)` 分支及通用 DashScope 分支统一接入该提取函数。
2. **增强 FFmpeg concat 鲁棒性与错误追踪**：
   - 在 `synthesize_slide_audio_with_timing` 与 `synthesize_slide_audio` 中，清洗 concat 列表中的 `//?/` 与 `\\?\` 前缀，保证 Windows 绝对路径标准兼容；
   - 引入降级保护策略：若第一阶段 `-c copy` 快速合并失败（如采样率、通道数不一致），自动回退至 `-c:a libmp3lame -q:a 2` 进行统一重编码拼接；
   - 捕获 FFmpeg 的 `stderr` 详细输出，避免吞掉关键错误日志。

## 四、涉及与修改代码清单
- `src-tauri/src/tts_service.rs`: 
  - 新增 `save_audio_from_bytes` 统一提取 JSON URL/Base64/报错信息；
  - 重构 `call_tts_api` 中的三个接口分支调用；
  - 增强 `synthesize_slide_audio_with_timing` 与 `synthesize_slide_audio` 的 concat 容错和重编码回退。
