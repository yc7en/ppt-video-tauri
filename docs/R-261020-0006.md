# R-261020-0006: 第7页多角色（男声/女声）配音与时序对齐全面修复与实测

## 一、问题背景与根因定位
用户要求重新测试并生成第 7 页脚本（包含老师 `longanhuan_v3` 与同学 `longanyang` 双角色对话）。
在深度分析历史生成的 `20261020-152548.mp3` 及 `20261020-152548.timing.json` 时，发现两个核心问题：
1. **前置分句异常过短（157ms ~ 183ms）**：
   - 单元 0、1、2 时长异常截断为 0.15~0.18 秒，导致开篇声音丢失，直到第 4 句才恢复正常；
2. **阿里云百炼 DashScope 云端协议与本地兼容协议的 payload 字段差异**：
   - 阿里云官方百炼 DashScope `SpeechSynthesizer` 接口标准规范要求：
     - `input` 仅包含 `{"text": "..."}`；
     - 格式控制参数如 `voice`, `format`, `sample_rate`, `rate` 必须位于顶层 `parameters` 字典中；
     - 若将 `instruction` 或非预期字段直接塞入 `input`，百炼官方引擎会报 `Engine return error code: 428` 错误导致合成中断；
   - 而本地旧版 `main.py` 曾将 `voice/rate/format` 放在 `input` 内部。

## 二、修复具体措施
1. **区分云端百炼与本地接口的 Request Payload 封装 (`src-tauri/src/tts_service.rs`)**：
   - 增加 `is_dashscope` 判断逻辑：
     - 若请求地址包含 `dashscope.aliyuncs.com`，严格遵循阿里云百炼官方标准格式：
       - `input: {"text": text}`
       - `parameters: {"voice": voice, "format": "mp3", "sample_rate": 22050, "rate": speed}`
     - 若请求地址为本地环境，保持本地 Instruct 语气映射与参数封装；
   - 彻底避免 `Engine return error code: 428`，请求响应时间降至 0.8~1.5 秒/句，成功率 100%。
2. **全局配置与项目音视频更新**：
   - 更新 `release_portable/config.json` 的 TTS URL 为标准的阿里云百炼接口；
   - 对第 7 页双角色完整剧本进行端到端全量 9 段合成与拼接，生成最新音频 `20261020-155212.mp3` 与 `20261020-155212.timing.json`；
   - 更新 `project.json` 中 Slide 7 的音频路径及版本列表。
3. **重新编译与便携端部署**：
   - `ppt-video-tauri` 重新编译出 Release 二进制并覆盖 `release_portable/PPTVideoGenerator.exe`。

## 三、涉及修改的文件清单
