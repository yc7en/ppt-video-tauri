# BugFix-261013-0002: 修复 Tauri WebView2 本地 PNG 图片加载失败

## 一、缺陷描述
PPT 解析成功后，进入文案编辑页面，左侧缩略图以及右侧主预览区的图片显示为空白或破损图片图标，导致用户无法参照幻灯片内容校对和撰写对应文案。

## 二、修复方法与实现
1. **根因定位**：
   - Tauri v2 默认禁用了 `asset:` 本地自定义协议对操作系统任意路径的访问，需要显式开启并设置作用域；
   - Windows 下包含中文或空格的绝对路径在通过 WebView2 的 `https://asset.localhost/` 访问时容易触发 URL 编码截断与跨域安全阻断。
2. **修复措施**：
   - **双重兜底方案**：
     1. 在 Rust 后端解析 PPT 或载入项目时，自动读取 PNG 文件并生成 Base64 Data URL 字符串（`image_data`），直接随 `SlideInfo` 传递至前端渲染，0 网络请求且 100% 可用；
     2. 在 `src-tauri/Cargo.toml` 中开启 `tauri = { features = ["protocol-asset"] }`，在 `tauri.conf.json` 中配置 `security.assetProtocol = { enable: true, scope: ["**"] }`；
     3. 前端使用 `slide.image_data || toFileUrl(slide.image_path)` 双通道渲染保障。

## 三、涉及与修改代码清单
- `src-tauri/Cargo.toml`: 引入 `base64 = "0.22"` 与 `protocol-asset` 特性
- `src-tauri/tauri.conf.json`: 声明 `security.assetProtocol` 权限作用域
- `src-tauri/src/models.rs`: `SlideInfo` 增加 `image_data: Option<String>` 字段
- `src-tauri/src/ppt_parser.rs`: 图片导出后读取 Base64 编码
- `src-tauri/src/project_manager.rs`: 加载已有项目时自动补齐缺失的图片 Base64
- `src/App.vue`: 前端模板优先使用 `slide.image_data`
