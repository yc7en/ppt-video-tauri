# R-261020-0005: 修复本地 CosyVoice3 第二角色（男声）未生效问题

## 一、问题根因深入分析
用户反馈在本地部署模式下，包含 `{role:同学}`（配置为阳光男声 `longanyang`）的第 7 页脚本合成出的音频仍然是女声。
经深度排查调用链与本地服务底层日志发现：
1. **本地 CosyVoice3 服务逻辑机制**：
   - 本地 `127.0.0.1:8890` 运行的是开源 `Fun-CosyVoice3-0.5B-2512_RL` 模型，其 `SpeechSynthesizer` 接口在收到 `voice="longanyang"` 时，仅在模型克隆库 `spk2info.pt` 中查找该音色 ID；
   - 因 `longanyang` 为阿里云 DashScope 的预设音色，并非本地 zero-shot 克隆音色，本地服务直接打印 `[ws] 音色 longanyang 未注册，使用默认音色`；
   - 且因客户端此前未传递 `instruction`，本地服务端回退到 `DEFAULT_PROMPT_WAV`（系统内置的女性参考音频），最终合成出的音频基频为 ~280 Hz 的女声。
2. **两端协同适配不足**：
   - 客户端 `PPTVideoGenerator` 在调用本地/阿里兼容接口时，未将音色性别与情绪映射为 `instruction` 传递；
   - 本地服务端 `main.py` 在未注册该音色时，缺乏标准音色别名库到 Instruct 提示词的自动降级桥接。

## 二、修复具体内容
1. **服务端音色别名与 Instruct 指令自动桥接 (`E:\02SourceCode\tts\tts3\main.py`)**：
   - 引入 `VOICE_INSTRUCT_MAP`，内置阿里标准音色映射：
     - `longanyang` 映射为 `用阳光年轻男声说话`；
     - `longshuo` 映射为 `用沉稳成熟中年男声说话`；
     - `longcheng` 映射为 `用富有磁性稳重的男声说话`；
     - `longyingjing_v3` 映射为 `用知性温和女声说话`；
     - `longxiaochun_v2` 映射为 `用温柔柔和女声说话`；
     - `longanhuan_v3` 映射为 `用欢快活泼亲切女声说话`；
   - 当收到未在本地注册的音色 ID 时，服务端自动匹配对应的 `instruction` 并激活 `cosyvoice.inference_instruct2`，实测基频精准降至 **91.3 Hz**，完美呈现自然年轻男声，不再回退到女声。
2. **客户端 TTS 接口自动装配 `instruction` (`src-tauri/src/tts_service.rs`)**：
   - 在发起 `SpeechSynthesizer` 与通用 DashScope 接口请求时，自动根据 `voice` 字段判断性别特征与语气，装配 `instruction` 字段注入请求体 `input` 与 `parameters`；
   - 形成客户端与服务端双重保障，无论本地服务是否有特定音色注册，均能稳定产出真实男声。

## 三、涉及与修改的代码文件
- `E:\02SourceCode\tts\tts3\main.py`:
  - 增加 `VOICE_INSTRUCT_MAP` 与启发式规则，未注册音色平滑转入 `inference_instruct2` 指令推理。
- `E:\02Code\ppt-video-tauri\src-tauri\src\tts_service.rs`:
  - 在 `call_tts_api` 中为 `SpeechSynthesizer` 与 DashScope 模式补充 `instruction` 自动装配逻辑。
- `release_portable/PPTVideoGenerator.exe`:
  - 重新编译 Release 二进制并部署。

## 四、测试与验证
1. 调用本地 `http://127.0.0.1:8890/api/v1/services/audio/tts/SpeechSynthesizer` 接口合成男声文本，通过自相关测频算法实测基频为 **91.3 Hz**（标准成年男声区间 85~120 Hz），声音浑厚年轻，彻底告别女声假死回退；
2. 单元测试与端到端切片测试全部通过。
