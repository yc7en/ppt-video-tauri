# BugFix-261020-0001: 修复多角色文案中次要角色未正确应用男声音色问题

## 一、缺陷描述
用户在项目 `归还比例达标降低利率操作-slide` 的第7页文案中配置了多角色对话脚本：
```text
{role:老师}
第三个问题：归还比例达标却没有修改入口。
...
{role:同学}
老师，我有一个问题想问一下，如果法院判了需要降低利率
...
{role:老师}
法院判决是一种特殊情况，这里没法操作。需要走钉钉流程特殊差异化利率申请解决。
{role:同学}
好的，老师，谢谢。
```
尽管系统预设有角色2为男声（`longanyang` 阳光男声），但在生成配音及合成视频时，`{role:同学}` 段落仍然被知性女声（`longyingjing_v3`）朗读，未切换至男生配音。

## 二、测试分析与根因排查
1. **真实接口与音色可用性验证**：
   - 使用 `cosyvoice-v3-flash` 模型直接请求 DashScope TTS 接口，指定 `voice: "longanyang"`，成功返回时长 5.669s 的音频，平均过零率（ZCR）1966 Hz，确认为标准男声音色，排除模型或音色参数不兼容问题。
2. **已有生成音频声学分析**：
   - 提取第7页用户生成的 `20261020-113857.mp3` 中“同学”与“老师”发言切片进行声学分析：
     - 同学切片：时长 5.357s，ZCR 2835 Hz（与知性女声完全吻合）；
     - 老师切片：时长 5.010s，ZCR 2853 Hz；
     - 证实当时生成的音频中，“同学”段落确实使用了 `longyingjing_v3` 女声。
3. **流程与状态脱节根因排查**：
   - **自动检测局限**：原 `detect_first_role_cmd` 仅检测文案中出现的第一个角色标签（`老师`），前端仅将 `roleConfigs[0]` 设为 `老师`，而对于后续出现的 `{role:同学}`，`roleConfigs[1].role_name` 始终为空字符串 `""`；
   - **界面交互错位**：原本的「多角色音色配置」面板仅存在于“步骤3：生成视频”页面。用户在“步骤2：编辑文案”撰写脚本并点击【生成配音】时，步骤2完全没有多角色配置视图，导致向 Rust 后端传递的 `role_configs` 中角色2名称为空；
   - **后端兜底规则**：Rust 端 `resolve_role` 在匹配不到角色名 `同学` 时，统一回退使用角色1（`longyingjing_v3` 知性女声）；
   - **步骤3不重调TTS**：用户在步骤3手动填写“角色2对应的角色名：同学”后，步骤3只有【开始合成视频】按钮，而视频合成直接使用已有音频文件，不会重新触发 TTS 合成；
   - **缺少实时保存**：在步骤3修改角色名称/音色/语速时，未触发 `save_project_cmd` 自动落盘；
   - **UTF-8 BOM 与空文本边界处理**：文案开头若含 BOM 字符 `\ufeff` 时，切分算法会在第一个角色前误创建一段角色为空的微小发音片段。

## 三、修复方法与实现
1. **前端多角色全量自动检测与绑定 (`autoDetectRoles`)**：
   - 在 `App.vue` 中实现 `autoDetectRoles()`，扫描全项目所有幻灯片脚本中的 `{role:XXX}` 标签；
   - 按照标签出现的次序，自动将未绑定的角色名填入空闲槽位（如：`老师` 绑定角色1，`同学` 自动绑定角色2）；
   - 在加载项目（`handleLoadProject`）、新建项目（`handleParsePpt`）、导入 Markdown（`handleImportMd`）以及文案输入（`handleScriptChanged`）时自动调用。
2. **在「步骤2：编辑文案」内嵌多角色音色配置面板**：
   - 在步骤2文案输入框上方嵌入可折叠的“🎭 多角色音色配置”条，直观展示角色1、角色2、角色3的角色名输入、音色下拉选择、语速滑块及默认兜底标签；
   - 支持实时修改角色对应关系，无需跳转步骤3即可在生成配音前完成核对与调整。
3. **角色配置变更自动持久化 (`handleRoleConfigChanged`)**：
   - 在步骤2与步骤3中，角色名称、音色及语速任何一项发生变动时，均立即触发 `save_project_cmd`，确保项目配置与界面状态始终同步落盘。
4. **Rust 端 BOM 清洗与防空片段加固**：
   - 在 `tts_service.rs` 的 `parse_script` 与 `segment_script` 中增加 `trim_start_matches('\u{feff}')` 清洗；
   - 在切分文本与句子分段时过滤纯空白与 BOM 字符，消除开头的无意义空白音频请求；
   - 增加 `detect_roles_cmd` 命令支持多角色扫描。
5. **用户项目音频修复**：
   - 为用户的 `归还比例达标降低利率操作-slide` 项目第7页重新合成了男声配音 `20261020-120500.mp3`（“同学”段落已采用 `longanyang` 阳光男声，时长 44.333s），并同步更新了 `project.json`。
