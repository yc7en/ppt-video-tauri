# BugFix-261013-0005: 修复点击打开输出目录未准确定位到 output 文件夹

## 一、缺陷描述
在步骤 3 视频合成完成后，界面提示视频已生成至指定路径，但点击旁边的【📁 打开输出目录】按钮后，系统打开的却是 Windows 的“文档”或“此电脑”，并没有打开包含生成的 MP4 视频的 `output` 文件夹。

## 二、修复方法与实现
1. **根因定位**：
   - 前端拼接路径为 `${project.value.project_dir}/output`，其中包含了正斜杠 `/`；
   - Windows 原生 `explorer.exe` 将正斜杠 `/` 视作命令行选项控制字符（如 `/n,`, `/select,`），导致将 `/output` 误识别为非法选项，路径解析失败从而降级打开默认的“用户文档”；
   - 此外，若已生成具体的 MP4 视频文件，直接将文件路径传给 `explorer.exe` 不会定位文件夹，必须使用 `/select,"<文件路径>"` 才能正确在资源管理器中定位并选中该文件。
2. **修复措施**：
   - 在 Rust 端 `open_path_cmd` 中强制使用 `path.replace('/', "\\")` 统一为 Windows 标准反斜杠路径；
   - 区分文件与目录：如果是文件路径，通过 `explorer /select,"<文件路径>"` 调起资源管理器并自动高亮选中生成的视频；如果是目录路径，自动 `create_dir_all` 确保存在后直接打开；
   - 在 `compose_video_cmd` 中，生成的 MP4 同时在便携根目录 `output/` 与项目目录 `projects/<stem>/output/` 双重沉淀，满足多场景查找需求。

## 三、涉及与修改代码清单
- `src-tauri/src/commands.rs`: `open_path_cmd`（反斜杠转义、`/select` 文件定位与目录确保）、`compose_video_cmd`（双重沉淀输出）
- `src/App.vue`: `handleOpenOutput`（优先传入 `lastVideoPath`，统一反斜杠拼接）
